The `better-helpdesk` package has eight entry points. Related guide: [Call the helpdesk from your own code](/docs/app/own-code).

| Entry point | Runs on | Exports |
| --- | --- | --- |
| [`better-helpdesk`](#better-helpdesk) | Server | `buildHelpdesk`, `postgresAdapter`, identity tokens, references, types |
| [`better-helpdesk/adapters`](#better-helpdeskadapters) | Server | The database adapters, the adapter contract and `migrate` |
| [`better-helpdesk/testing`](#better-helpdesktesting) | Tests | `runAdapterTests`, the checks an adapter of your own must pass |
| [`better-helpdesk/widget`](#better-helpdeskwidget) | Browser | The widget and the support page, for React and as custom elements |
| [`better-helpdesk/admin`](#better-helpdeskadmin) | Browser | The agent UI |
| [`better-helpdesk/rich`](#better-helpdeskrich) | Server or browser | The message format: parser and renderer |
| [`better-helpdesk/next`](#better-helpdesknext) | Build | `withHelpdesk` for `next.config` |
| [`better-helpdesk/widget.js`](#better-helpdeskwidgetjs) | Browser | The standalone widget script |

The package is ESM only and ships its type declarations. Its peer dependencies are `react` and `react-dom` (React 19) and the driver of the host's database, which only a host on that database installs: `pg` for Postgres, `mysql2` 3.24 or newer for MySQL, `tedious` 20 and `tarn` 3 for SQL Server, and none for SQLite; it requires Node.js 22.19 or newer.

## better-helpdesk

| Export | Kind | What it is |
| --- | --- | --- |
| `buildHelpdesk(config)` | function | Builds the helpdesk from a [`HelpdeskConfig`](/docs/reference/configuration). Throws on [invalid configuration](/docs/reference/configuration#startup-checks). |
| `postgresAdapter({ pool })` | function | The `DatabaseAdapter` over a `pg.Pool`, for the `db` option. |
| `mysqlAdapter({ pool })` | function | The `DatabaseAdapter` over the host's mysql2 pool, MySQL 8.4 or newer. The pool must be created with `timezone: 'Z'`; the adapter refuses one that converts times in another zone. |
| `mssqlAdapter(config)` | function | The `DatabaseAdapter` over SQL Server 2022 or newer. `config` is what Kysely's `MssqlDialect` takes: the host's `tedious` and `tarn` modules and its connection. |
| `sqliteAdapter({ database })` | function | The `DatabaseAdapter` over a SQLite database the host opened, from `node:sqlite` or `better-sqlite3`. It turns foreign keys on and refuses to start if they stay off. |
| `kyselyAdapter({ dialect, family })` | function | A built-in adapter over any Kysely dialect of a family Better Helpdesk knows. `postgresAdapter` is this with Kysely's `PostgresDialect`. |
| `migrate(adapter)` | function | Applies the migrations through a built-in adapter, as [`better-helpdesk-migrate`](/docs/operations/cli#better-helpdesk-migrate) does; returns the names of the ones it applied. |
| `createAdapter(input)` | function | Turns an `AdapterInput`, the contract a custom adapter implements, into a `DatabaseAdapter`: it sets ids and defaults and converts values to and from what the input supports. |
| `createStore(adapter)` | function | The `HelpdeskStore` over an adapter, for code that runs without `buildHelpdesk`. |
| `helpdeskModel` | object | Every table and field, with its kind, whether it may be null, its default and its references. |
| `signIdentityToken(payload, secret, options?)` | function | Signs an identity token. |
| `verifyIdentityToken(token, secret)` | function | Returns the `Identity` a token vouches for, with `isAgent: false`, or `null` when it is forged, malformed or expired. |
| `formatReference(prefix, number)` | function | `formatReference('ACME', 1042)` is `ACME-1042`. |
| `parseReference(prefix, value)` | function | The number in a reference such as `ACME-1042`, matched case-insensitively, or `undefined`. |
| `HelpdeskError` | class | An error with an HTTP `status` and, for a bulk change, the failed `ids`. The handler answers it with that status. |
| `BuiltHelpdesk` | type | What `buildHelpdesk` returns. |
| `Conversation`, `Message` | type | Rows of [`conversation`](/docs/database/tables#conversation) and [`message`](/docs/database/tables#message). |
| `HelpdeskStore` | type | The query layer, `buildHelpdesk(...).store`. |
| `DatabaseAdapter`, `AdapterInput`, `Capabilities`, `Where`, `OrderBy`, `FindQuery`, `Notification` | type | The adapter contract. |
| `HelpdeskEvent` | type | See [Events](/docs/app/events). |
| `IdentityClaims` | type | The claims of an identity token. |

Every type in the configuration module is exported as well: `HelpdeskConfig`, `InboxConfig`, `BusinessHours`, `Identity`, `HelpdeskUser`, `HelpdeskOrg`, `HostLink`, `LinkContact`, `LinkCompany`, `HelpdeskEmail`, `StorageAdapter`, `AiAdapter`, `HelpResult`, `InboundMessage`, `CustomFieldDef`, `Locale` and `ResolvedConfig`. The default lists, such as the statuses and the default types, are not exported.

## better-helpdesk/adapters

What a host needs to pick or write a database adapter, without the rest of the server: `postgresAdapter`, `mysqlAdapter`, `mssqlAdapter`, `sqliteAdapter`, `kyselyAdapter`, `createAdapter`, `migrate` and `helpdeskModel`, with the contract's types. The same names are exported from `better-helpdesk`. None of them imports a database driver: the host passes its own connection.

## better-helpdesk/testing

`runAdapterTests({ name?, adapter, reset })` registers vitest tests that hold an adapter to the contract the store relies on: every kind of value read back as written, NULL compared as SQL does, exact text unless `insensitive`, search characters taken literally, NULLs ordered where asked, times and numbers compared and ordered by value, paging and selected fields, conditions through another table, counted updates and in-place increments, one winner of simultaneous compare-and-swap updates, a row read for update held until its transaction ends, whole transactions, a repeated primary key refused, and the partial verified-identity key held. `adapter` returns the adapter (an `AdapterInput` or a `DatabaseAdapter`) over a database that has the tables of `helpdeskModel`; `reset` empties them before each test. `vitest` 4 or 5 is an optional peer dependency, needed only here. `examples/adapters/database-memory.ts`, an adapter that keeps everything in memory, passes it, and the built-in adapters run it in the integration suite.

## better-helpdesk/rich

The message format that messages and canned replies are written in, and a renderer for it. The module has no hooks and no `'use client'`, so it renders on the server as well, for example in an email template.

The format is plain text with a small set of Markdown: `**bold**`, `_italic_`, `++underline++`, `[label](url)`, bare `http` and `https` links, lists whose lines start with `-`, `*` or `•`, or with a number and `.` or `)`, blank lines between paragraphs, and code blocks between lines of three or more backticks.

| Export | Signature | What it does |
| --- | --- | --- |
| `RichText` | `(props: { text: string; compact?: boolean; hosts?: boolean; code?: (text: string) => ReactNode; reference?: (reference: string) => ReactNode }) => ReactNode` | Renders a message. `compact` renders inline only, with lists as `•` lines. `hosts` shows where each labeled link goes. `code` renders code blocks. `reference` renders each conversation reference outside links and code. |
| `parseRich` | `(text: string) => Block[]` | Parses a message into paragraphs, lists and code blocks. |
| `parseInline` | `(text: string) => Inline[]` | Parses one line into text, bold, italic, underline and link runs. |
| `plainText` | `(text: string) => string` | The words without the markers. |
| `safeHref` | `(href: string) => string \| null` | The target when it starts with `http://`, `https://` or `mailto:`, otherwise `null`. |
| `unlabelLinks` | `(text: string) => string` | Rewrites `[label](url)` as `label (url)`. |
| `fence` | `(text: string) => string` | Wraps text in a code block whose backtick lines are longer than any run inside it. |
| `Block`, `Inline` | type | The parsed shapes. |

## better-helpdesk/next

```js title="next.config.mjs"
import { withHelpdesk } from 'better-helpdesk/next';

export default withHelpdesk({ trailingSlash: true });
```

`withHelpdesk(nextConfig = {})` returns the config with `better-helpdesk` added to `transpilePackages`, keeping any packages already listed.

## better-helpdesk/widget.js

The minified standalone widget, the file `dist/widget.js`, for a page without React. See [Script tag](/docs/widget/reference#script-tag).

`better-helpdesk/package.json` is exported too.
