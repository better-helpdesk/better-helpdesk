---
title: Database
description: The tables of the helpdesk schema, every column with its type and default, and what each table holds.
---

Better Helpdesk keeps everything in one Postgres schema, `helpdesk`, in the host's database. [`better-helpdesk-migrate`](/docs/reference/cli#better-helpdesk-migrate) creates and updates it. The types below are Postgres's. Ids are `uuid`, generated by the app, and every timestamp is `timestamptz`, written from the app's clock; the defaults the columns still carry are left from before and unused. The TypeScript types (`Conversation`, `Message`) use the column names in camel case: `contact_id` is `contactId`. Related guide: [Report from your own database](/docs/guides/reporting).

<Callout>
  Until version 1.0, a minor release can change, rename or drop columns. The release notes say when one does.
</Callout>

| Table | Holds |
| --- | --- |
| [`company`](#company) | Organizations, mapped to the host's by `external_org_id` |
| [`contact`](#contact) | People: customers, visitors, leads |
| [`identity`](#identity) | The ways a contact is known |
| [`agent`](#agent) | Support team members |
| [`conversation`](#conversation) | Conversations |
| [`participant`](#participant) | Contacts added to a conversation besides its own |
| [`message`](#message) | Messages and internal notes |
| [`conversation_event`](#conversation_event) | A conversation's timeline |
| [`attachment`](#attachment) | Files, by storage key |
| [`canned_reply`](#canned_reply) | Saved answers |
| [`setting`](#setting) | Values the package and agents keep |
| [`deal`](#deal) | Deals |
| [`activity`](#activity) | Notes, calls, meetings and host events on a timeline |
| [`job`](#job) | Queued work |
| [`rate_limit`](#rate_limit) | Hourly counters |
| [`conversation_tag`, `contact_tag`, `company_tag`](#tags) | Tags, in the order they were added |
| [`counter`](#counter) | The next conversation number |

The migrator records what it applied in `migration`, and takes `migration_lock` while it runs. `__migrations` lists the migrations from before the adapters, which the first of the new ones reads; the sequence `reference_seq` is no longer used.

## rate_limit

| Column | Type | Null | Default | Notes |
| --- | --- | --- | --- | --- |
| `key` | `text` | no | | What is counted, such as `ip:{address}` or `contact:{id}`. |
| `window_start` | `timestamptz` | no | | The start of the hour. |
| `count` | `integer` | no | `0` | |

The primary key is `(key, window_start)`. Windows older than a day are deleted as new hits arrive.

## Tags

`conversation_tag`, `contact_tag` and `company_tag` hold one row per tag, unique per owner. Conversation tags are lower-cased; a contact's include the answers to inbox qualifying questions.

| Column | Type | Null | Default | Notes |
| --- | --- | --- | --- | --- |
| `conversation_id`, `contact_id` or `company_id` | `uuid` | no | | The owner; its tags go with it. |
| `tag` | `text` | no | | Indexed. |
| `position` | `integer` | no | | The order the tag was added in, from 0. |

The primary key is the owner and `tag`.
