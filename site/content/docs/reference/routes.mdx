`helpdesk.handler(request: Request): Promise<Response>` serves every route below under `basePath` (`/api/helpdesk` by default). Paths match with or without a trailing slash; the widget and the agent UI request them with one. Ids are UUIDs. Request and response bodies are JSON unless a row says otherwise. Related guides: [Receive email](/docs/email/receive), [Run jobs and retention](/docs/operations/jobs).

<Callout type="warn">
  The `widget/*` and `agent/*` routes are the contract between the handler and the widget and agent UI that ship with it. They can change in any minor release and are not an API for other callers. Host code calls the helpdesk through the functions `buildHelpdesk` returns, as in [Call the helpdesk from your own code](/docs/app/own-code). `inbound`, `jobs` and `rate` are the routes meant for callers outside the package.
</Callout>

```ts title="app/api/helpdesk/[...slug]/route.ts"
import { helpdesk } from '@/lib/helpdesk';

const handle = (request: Request) => helpdesk.handler(request);
export { handle as GET, handle as POST, handle as PATCH, handle as PUT, handle as DELETE, handle as OPTIONS };
```

## Callers

| Caller | How the handler knows them | Routes |
| --- | --- | --- |
| Customer | `identify(request)`; else, when `identityTokenSecret` is set, an `x-helpdesk-identity` token signed with it; else an `x-helpdesk-visitor` token | `widget/*` |
| Agent | `identify(request)` returning `isAgent: true`. 401 without an identity, 403 when it is not an agent, 403 on a change from a `viewer` | `agent/*` |
| Anyone | Nothing | `health` |
| Email link | The signature in the query string | `rate` |
| Mail relay | `Authorization: Bearer {inboundWebhookSecret}` | `inbound` |
| Scheduler | `Authorization: Bearer {jobsSecret}` | `jobs` |

A visitor token is issued by `POST widget/conversations` to an anonymous visitor, and stops working after 30 days unused. An invalid identity token is refused with 401.

A customer **can see** a conversation they opened, one they were added to as a participant, and one shared with a company the caller's identity lists in `orgs`. A conversation they cannot see answers 404. Routes marked **author** also require the caller to be the conversation's own contact, and answer 403 otherwise.

## Widget

| Method | Path | Who | What it does |
| --- | --- | --- | --- |
| `GET` | `widget/session` | Anyone | The caller, their conversations and what the widget shows; `?inbox=`, `?locale=` and `?org=`, the organization the widget files under, which `resolveTier` is asked about for the priorities on offer. |
| `POST` | `widget/conversations` | Customer, or a visitor on a `public` inbox | Opens a conversation; see [the body](#opening-a-conversation). |
| `GET` | `widget/conversations/{id}` | Can see | The conversation, its public messages and its attachments. |
| `POST` | `widget/conversations/{id}/messages` | Can see | Adds a message. |
| `PATCH` | `widget/conversations/{id}` | Author | Shares it with the company, or marks it resolved. |
| `POST` | `widget/conversations/{id}/rating` | Author | Rates it `good` or `bad`, with an optional comment. |
| `POST` | `widget/conversations/{id}/seen` | Can see | Marks it read by its author. |
| `POST` | `widget/conversations/{id}/attachments` | Author | Starts an upload and answers a presigned form. |
| `POST` | `widget/conversations/{id}/attachments/{attachmentId}/complete` | Author | Marks the upload done. |
| `GET` | `widget/conversations/{id}/attachments/{attachmentId}` | Can see | Redirects to a presigned download URL. |
| `GET` | `widget/help` | Anyone | Searches the host's documentation through `help`; `?q=` and `?locale=`. |
| `GET` | `widget/events` | Customer | An event stream of changes to the conversations the caller can see, internal notes left out. 404 without [`realtime`](/docs/reference/configuration#conversations). |

A conversation in `widget/session` and `widget/conversations/{id}` carries its `kind`, `chat` or `ticket`, `typing`, true while an agent writes a reply, `respondBy`, the time the team aims to answer by while nobody has, and `ratingScore`. `widget/session` says with `realtime` whether `widget/events` is there, lists under the inbox the `priorities` this caller may pick with their descriptions (`null` for a visitor or a tier the inbox does not offer them to), and carries `priorityLabels` and `ratingScale`.

`POST widget/conversations/{id}/rating` takes `{ rating: 'good' | 'bad', comment? }` on the default scale and `{ score: 1..5, comment? }` when `ratingScale` is 5; the other shape is refused with 400.

## Agent

Every route here requires an agent. The `agent/deals`, `agent/canned` and `agent/overview` routes answer 404 when [`features`](/docs/reference/configuration#crm) switched their section off. A `viewer` may call every `GET`, and of the rest only `PATCH agent/me`, `POST agent/notifications/seen` and the `agent/views` routes; anything else answers 403. Once any agent has the `supervisor` role, `PUT agent/settings`, `DELETE agent/agents/{id}` and `GET agent/audit` answer 403 to everyone else.

Every request that is not a `GET` and succeeded is written to [`audit_log`](/docs/database/tables#audit_log) with the agent, the route, the id in its path and the names of the fields it sent.

## Rate

| Method | Path | Caller | What it does |
| --- | --- | --- | --- |
| `GET` | `rate` | Email link | An HTML page that asks the customer to confirm the rating in the link, with a button. |
| `POST` | `rate` | Email link | Records the rating and answers an HTML page. A `bad` rating opens the conversation again. |

The links come in a [`customer-reply`](/docs/email/messages#customer-reply). A forged or expired link answers 404. A conversation already rated answers 200 and records nothing; one that is no longer resolved, or was merged, answers 409. With `ratingScale: 5` the link names a score from 1 to 5, and a score of 1 or 2 opens the conversation again.

| Method | Path | Caller | What it does |
| --- | --- | --- | --- |
| `GET` | `health` | Anyone | `{ ok: true }` once the database answered one query, `{ ok: false }` with 503 otherwise. For your status page or load balancer. |

## Inbound

| Method | Path | Caller | What it does |
| --- | --- | --- | --- |
| `POST` | `inbound` | Mail relay | Takes one raw message (`message/rfc822`) as the body and checks DKIM. Signed mail from the conversation's contact or a participant is added to the conversation that its `In-Reply-To` or `References`, or a `+{reference}` recipient address, points to. Any other mail opens a conversation in `inboundInbox`. Answers 202 with `{ ok: true }`. |

Without `inboundWebhookSecret`, or with another bearer token, it answers 401. The message is refused with 400 when empty, and with 413 over 25 MiB or when its headers exceed 64 KiB. Mail from a blocked address, and unsigned automated mail (an out-of-office or a bounce), is accepted with 202 and not stored; signed automated mail that answers a conversation is stored there as an internal system note. A message already stored, by Message-ID, is accepted and ignored. Signed mail from a sender over their hourly budget answers 429; unsigned mail over budget is dropped quietly.

## Jobs

| Method | Path | Caller | What it does |
| --- | --- | --- | --- |
| `POST` | `jobs` | Scheduler | Runs `helpdesk.runJobs()` and answers its report. |

Without `jobsSecret`, or with another bearer token, it answers 401.

`runJobs({ budgetMs }: { budgetMs?: number } = {})`, with `budgetMs` 20,000 by default, wakes due snoozes, queues due reminders, queues due SLA notices, applies `retentionDays`, then works through due jobs until the budget is spent. It returns:

A failed job runs again after 2, 4, 8 and 16 minutes, and is kept with its last error after the fifth attempt. The job kinds are on [Database](/docs/database/tables#job).

## Origins and CORS

- A mutation is any method but `GET`, on any route but `rate`, `inbound` and `jobs`. A `POST` mutation must send `Content-Type: application/json` (415 otherwise). `health` takes only `GET`.
- A mutation that carries an `Origin` header must come from the origin of `adminUrl`, or, on a `widget/*` route, from an origin in an inbox's `allowedOrigins`. Otherwise it answers 403.
- `widget/*` responses to an allowed origin carry CORS headers: methods `GET, POST, PATCH, OPTIONS`, headers `content-type, x-helpdesk-visitor, x-helpdesk-identity`, max age 600 seconds. Agent routes never do.
- `OPTIONS` on any path answers 204.

## Errors

| Status | Body |
| --- | --- |
| 400 | `{ error: 'Invalid request', issues }` for a body that fails validation, where `issues` lists the paths of the invalid fields; `{ error: 'Invalid JSON' }` for a body that does not parse; otherwise `{ error }`. |
| 404 | `{ error: 'Not found' }` for an unknown route or a record the caller may not see. |
| 413 | `{ error: 'Too large' }` for a JSON body over 256 KiB or an inbound message over 25 MiB; `{ error: 'File too large' }` for an upload over `maxAttachmentBytes`; `{ error: 'Headers too large' }` for inbound headers over 64 KiB. |
| 500 | `{ error: 'Internal error' }`; the error is logged. |
| Other | `{ error, ids? }`, where `ids` lists the conversations a bulk change failed on. |

## Limits

| Limit | Value |
| --- | --- |
| Anonymous conversations, messages and uploads, per IP address (IPv6 per /64) | `anonymousRateLimit` an hour, 20 by default |
| Signed-in customer's conversations, messages and uploads | `customerRateLimit` an hour, 60 by default |
| Receipts | 200 an hour |
| New-conversation notices to agents | 200 an hour, each for host users and for everyone else |
| AI triage | 100 an hour, each for host users and for everyone else |
| Inbound email per sender address | 30 an hour, signed and unsigned counted apart |
| Inbound email per sender domain | 100 an hour, signed and unsigned counted apart; a signed reply from someone on the thread is not counted |
| Message length | 20,000 characters |
| JSON body | 256 KiB |
| Inbound message | 25 MiB |

Over a customer limit, the route answers 429. Over the receipt, notice and triage caps, the conversation is stored and the email or triage is skipped.
