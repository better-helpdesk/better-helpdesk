---
title: Email messages
description: Every HelpdeskEmail kind the email adapter receives, its fields, and when it is sent.
---

The `email.send(message)` adapter receives a `HelpdeskEmail`, a union of five kinds told apart by `kind`. The package decides when to send and to whom; the adapter decides how the message looks and how it is delivered. Every message is sent from a job, so it goes out when [`runJobs`](/docs/reference/routes#jobs) runs, and a throw from `send` retries the job. Related guide: [Send email](/docs/email/send).

| `kind` | To | Sent when |
| --- | --- | --- |
| `customer-reply` | The customer | An agent posts a reply that is not internal |
| `customer-receipt` | The customer | A conversation opens in an inbox with `receipt: true` |
| `agent-new` | Agents | A conversation opens, or a customer writes on a resolved one |
| `agent-reminder` | Agents | A customer has waited longer than the inbox's `reminderAfterHours` |
| `agent-mention` | The agents picked | An agent picks teammates with `@` in an internal note |

Every kind has these fields:

## customer-reply

<TypeTable
  type={{
    body: { type: 'string', required: true, description: "The agent's reply as written, with its Markdown formatting." },
    agentName: { type: 'string', required: true, description: <>The replying agent's name, or <code>''</code>.</> },
    subject: {
      type: 'string',
      description: "What the customer called the conversation. Absent when the conversation's first customer message is unverified.",
    },
    replyTo: { type: 'string', description: <><code>replyToAddress(reference)</code>, when configured.</> },
    inReplyTo: { type: 'string', description: 'The Message-ID of the latest inbound email in the conversation, for threading.' },
    ratingLinks: {
      type: '{ good: string; bad: string }',
      description: 'Present when the conversation is resolved, not yet rated and not merged.',
    },
  }}
/>

The job is queued two minutes after the reply and skipped when the customer has seen the reply in the widget by then, or the contact has no email address.

Each rating link opens `{basePath}/rate/` on the origin of `adminUrl`, with a signed query string, and is valid for 30 days. The page asks for confirmation with a button, so a mail scanner that follows the link records nothing. A `bad` rating opens the conversation again. The signing key is generated on first use and stored in the `setting` table.

Receipts are capped at 200 an hour across the whole helpdesk.

## agent-new and agent-reminder

Both kinds share one shape.

<TypeTable
  type={{
    subject: {
      type: 'string',
      required: true,
      description: "The conversation's title, else its subject, else the first 80 characters of the customer's text.",
    },
    body: {
      type: 'string',
      required: true,
      description: "The customer's first message, at most 1,000 characters. For a reopened conversation, the message that reopened it.",
    },
    url: { type: 'string', required: true, description: <>The conversation in the agent UI, <code>{'{adminUrl}'}/conversations/{'{id}'}/</code>.</> },
    reopened: { type: 'boolean', description: <><code>true</code> on an <code>agent-new</code> sent because a customer wrote on a resolved conversation.</> },
  }}
/>

Recipients are the agents who have an email address, have not been removed and have opened the agent UI in the last 30 days. When the conversation's assignee is one of them, only the assignee. Notices of new conversations are capped at 200 an hour, counted apart for the host's signed-in users and for everyone else.

An `agent-reminder` goes once per wait, from `runJobs`, and not for a conversation that is resolved, snoozed or from a blocked contact.

## agent-mention

<TypeTable
  type={{
    subject: { type: 'string', required: true, description: <>As for <code>agent-new</code>.</> },
    body: { type: 'string', required: true, description: 'The internal note, at most 1,000 characters.' },
    url: { type: 'string', required: true, description: 'The conversation in the agent UI.' },
    authorName: { type: 'string', required: true, description: <>The note's author: their name, else their email, else <code>''</code>.</> },
  }}
/>

Sent to each agent picked in the note who has an email address and has not been removed from the team, except the author.

## Recorded sends

After a send, the conversation's timeline gets an `email.sent` row in [`conversation_event`](/docs/database/tables#conversation_event) with the kind and recipients. A reopened `agent-new` is recorded as `agent-reopened`.
