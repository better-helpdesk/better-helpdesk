The package installs two commands, run with `npx` from the host app. Both open one connection to the database the URL names, through the driver the host installed, and close it on exit. Related guide: [Switch from another helpdesk](/docs/operations/switching).

## Environment

Both commands read the same variables.

| Variable | Meaning |
| --- | --- |
| `HELPDESK_DATABASE_URL` | Connection string. Read first. Its scheme picks the database: `postgres://` or `postgresql://` (through `pg`), `mysql://` (`mysql2`, in UTC), `mssql://` or `sqlserver://` (`tedious` and `tarn`; `?encrypt=false` and `?trustServerCertificate=true` are passed on), and `file:` or a path ending in `.db`, `.sqlite` or `.sqlite3` (Node's own `node:sqlite`). |
| `APP_DATABASE_URL` | Used when `HELPDESK_DATABASE_URL` is unset. |
| `DATABASE_SSL` | Postgres only. `true` turns on TLS and verifies the server's certificate. `no-verify` turns on TLS without verifying it, for a self-signed certificate. A `sslmode` in the connection string takes precedence over both. |

Without a connection string, the command prints `HELPDESK_DATABASE_URL or APP_DATABASE_URL must be set` and exits with status 1. With a scheme it does not know, or without the driver the scheme needs, it says so and exits with status 1.

## better-helpdesk-migrate

```sh
HELPDESK_DATABASE_URL=postgres://user:password@localhost:5432/app npx better-helpdesk-migrate
```

Applies the package's migrations: it creates the `helpdesk` schema and its tables on the first run and brings them up to date on later ones. Applied migrations are recorded in `helpdesk.migration`; an install that drizzle migrated before keeps its history in `helpdesk.__migrations`, and only what it lacks runs. A lock keeps two runs from applying the same migration. It takes no arguments and prints the migrations it applied, or `helpdesk: up to date`.

## better-helpdesk-import

```sh
npx better-helpdesk-import contacts <file.csv> [--lead-stages a,b,c]
npx better-helpdesk-import canned <file.csv>
```

Imports contacts and their companies, or canned replies, from a CSV file. The file is read and parsed before the connection opens, so a malformed file writes nothing. Running an import again adds what is new and changes nothing an agent edited.

| Argument | Meaning |
| --- | --- |
| `contacts` or `canned` | What the file holds. |
| `<file.csv>` | Path to the file. |
| `--lead-stages a,b,c` | The host's `leadStages`, for `contacts`. Unset, the package's defaults: `lead`, `qualified`, `customer`, `churned`. |

Any other arguments print the usage line and exit with status 1.

### CSV format

RFC 4180: comma-separated, fields in double quotes when they hold commas, quotes or line breaks, a quote inside a quoted field doubled. The first row is the header; its names are trimmed and lower-cased, and values are trimmed. Blank rows are skipped. A leading byte order mark is ignored. A quote that never closes, or text after a closing quote, stops the import with the line number and exit status 1.

### contacts

| Column | Required | Meaning |
| --- | --- | --- |
| `email` | yes | Matches an existing contact, case-insensitively. A row without a usable address is skipped. |
| `name` | | Up to 200 characters. |
| `company` | | Company name, up to 200 characters. |
| `domain` | | Company domain, up to 200 characters. |
| `tags` | | Separated by `;` or `\|`; lower-cased, each up to 50 characters, at most 50 per contact. |
| `lead_stage` | | One of the lead stages, matched case-insensitively. Others are left out. |

The company is found by `domain` when the row has one, else by `company` name, and created when missing, named after the domain when the row has no `company`; an existing company is never renamed. A company found by name without a domain takes the row's domain.

A new contact is created with the row's values. An existing contact only gains what it lacks: empty fields are filled and new tags are added.

### canned

| Column | Required | Meaning |
| --- | --- | --- |
| `title` | yes | Up to 200 characters. |
| `body` | yes | Up to 20,000 characters. |
| `locale` | | `en`, `de` or `fr`. Anything else saves the reply for any language. |

A row without a title or a body, or over either limit, is skipped. A reply whose title and locale match an existing one is left alone.

### Output

Each value left out prints a note to stderr, such as `helpdesk: row 4: no usable email, skipped`, where the row number counts the header as row 1. The last line counts the rows:

```txt
helpdesk: 12 created, 3 updated, 1 unchanged or skipped
```
